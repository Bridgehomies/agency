# SEO implementation — 6 October 2026

Bridge Homies is positioned as a software development agency. Existing blog posts remain available and indexable; no new articles were added.

## Evidence

The supplied Search Console export covers **the last three months**, not just today. Its Pages table contains 1,298 clicks; `/blog/submit` across www and non-www accounts for 1,198 (92.3%). `/ai-ml-development` has 1,054 impressions and zero clicks, `/mobile` 555 and zero, and `/software` 508 and zero. The Queries table shows 300 impressions for “ml model engineering services” and 117 for “mlops consulting services,” both with zero clicks. Aggregated query and page data do not establish which query produced impressions on a particular page.

The live homepage was also checked at https://www.bridgehomies.com/ before changes. It promoted Submit Blog in the footer and exposed its detailed agency overview only as screen-reader content.

## Implemented

- Homepage title, share metadata, and visible copy foreground software development. Its existing agency overview is visible inside main content with service and case-study links.
- Kept ML model engineering as the AI/ML service page's specific search target, adding “Services” to its title.
- Added the custom software page's own canonical and Open Graph metadata; its H1 now describes custom software development.
- Standardized www canonical URLs and structured-data entity references on service, product, testimonial, legal, and case-study pages. Removed the root layout's homepage canonical fallback, which previously leaked into pages without overrides.
- Removed duplicate web-development JSON-LD from the client component, retaining the server-rendered schema.
- Fixed project enquiry links on software, web development, mobile, and UI/UX pages to reach `/contact`.
- Added service destinations to the main menu, corrected homepage section destinations from subpages, and gave each menu dropdown independent state.
- Removed Blog from the main menu and Submit Blog from the sitewide footer. Blog remains reachable in the footer.
- Marked guest submission and editorial policy pages noindex, follow. Removed the submission robots disallow so crawlers can read noindex. Ordinary posts stay indexed.
- Removed sitemap additionalPaths entries that overrode editorial exclusions; added the MLOps source mapping. Lower sitemap priority for blogs is organizational and does not force Google to prioritize service pages.
- Added a real 1200×630 social-preview image and replaced missing AI/ML, mobile, and blog social-image paths. Corrected the design-page schema logo path.
- Added MLOps to the existing service discovery document, llms.txt.

## Validation

- `next build --webpack` passed, generating 109 pages. Called directly to avoid the package build script's automatic IndexNow submissions before deployment.
- `next-sitemap` completed successfully.
- `node scripts/verify-seo.mjs` passed across 19 generated pages, checking self canonicals, local social-image existence, www schema references, noindex tags, duplicate web-service schema, homepage agency copy, and sitemap exclusions.
- Social preview visually inspected.
- Standalone TypeScript validation still reports existing errors in the inactive booking route, terms page, and calendar component. Next's existing configuration skips build type errors; successful build does not mean a clean type check.

## Deployment and measurement

Changes are local and have not been deployed or submitted to search engines. After deployment, verify live canonicals/noindex and resubmit the sitemap in Search Console. Allow recrawling before judging outcomes.

Compare the next 28 days against the preceding 28 days for the homepage, five core service pages, and MLOps. Track service impressions, clicks, CTR, and qualified project enquiries separately from blog traffic. Expect total clicks to fall as guest-submission traffic leaves the index; that is intentional. The change would fail its business objective if service visibility and qualified enquiries do not improve after recrawling and sufficient observation. Search Console URL Inspection should show service pages eligible for indexing with matching declared and Google-selected canonicals, while submission pages eventually show excluded by noindex.
